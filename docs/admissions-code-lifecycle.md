# القبول وأكواد الطلاب

## تشغيل دورة القيد الرسمي

1. افتح «القبول والقيد»، ثم «فترات القبول». اختار فترة واحدة للتجربة وفعّل «تفعيل دورة القيد الرسمي لهذه الفترة» بعد تحديد صلاحيات الموظفين واعتماد إجراءات القيد وقرارات الوزارة.
2. استخدم «تحتاج مراجعة» لفتح الطلب. شؤون الطلاب تقدر تطلب استكمال البيانات ويصحح الطالب نفس الطلب من إيصال المتابعة، أو تعتمد التنسيق في المستوى الأول والتحويل في المستوى الثاني.
3. طالب التحويل المقبول مبدئيًا يستخدم كوده وحسابه في الخدمات المسموحة. «متابعة التحويلات» تعرض المنتظرين، و«جاهز لتأكيد القيد» تعرض من وافقت عليهم الوزارة وما زال القيد قيد الاستكمال.
4. سجل خطاب الوزارة بصيغة PDF. عند الرفض، يظل كود الطالب محفوظًا ويُفتح بند لمتابعة إخطار الطالب وبند للتسوية المالية. الحسابات تسجل مرجع التسوية المعتمدة.
5. استخدم «التحقق من القيد السابق» لتوثيق سجل قديم بمرجع وتاريخ سريان. إجمالي «قوة المعهد الرسمية» يضم السجلات التي تأكد قيدها. قائمة «قيد غير متحقق» تعرض السجلات النشطة التي تحتاج مراجعة.
6. بعد التجربة، راجع أعداد القيد والتعارضات مع شؤون الطلاب. يمكن إيقاف تطبيق الدورة على الاعتمادات الجديدة من إعدادات الفترة. الحالات والأكواد التي اتسجلت في الدورة تظل محمية وقابلة للقراءة.

في «تدقيق أكواد الطلاب»، «حجز الكود التالي» يستبعد الكود مؤقتًا بعد مراجعة المعاينة وتأكيد السبب. «فك الحجز» يرجّعه للتخصيص بعد مراجعة خلوه من الملكية والسجلات المرتبطة. حماية الكود الدائم تبدأ عند تخصيصه في دورة القيد الجديدة. إجراءات التحرير الإداري للأكواد القديمة تنطبق على الأكواد خارج هذه الحماية.

## الطالب الجديد أو المحوّل

1. من «القبول وأكواد الطلاب»، افتح «فترات القبول» وحدد السنة وميعاد الفتح والقفل. فعّل الفترة.
2. من صفحة روابط ورموز الدخول، جهّز دعوة القبول للطالب. الدعوة لازم تكون صالحة والفترة مفتوحة.
3. راجع الطلب والبيانات الأكاديمية، وبعدها وافق عليه. نفس الشرط بيطبق على الطالب الجديد والمحوّل: بعد قفل الفترة، لازم تفتحها تاني قبل إصدار كود جديد.
4. سنة `2026-2027` بتستخدم البادئة `27`، وسنة `2027-2028` بتستخدم `28`. أول رقم في البادئة الفاضية هو `0001`، يعني `280001`. لو فيه أكواد مستخدمة أو محجوزة بالبادئة دي، النظام بيحافظ عليها وبيكمّل بعدها. الفجوات مش بتتستخدم تلقائيًا قبل مراجعتها وتحريرها.

## تصحيح الإعدادات الموجودة

اختار السنة من قائمة السنين الموجودة في قاعدة البيانات. البادئة بتتحدد تلقائيًا. استخدم «مراجعة تصحيح بدايات الأعوام» بحساب مدير النظام، وراجع الكود التالي قبل التأكيد. التصحيح بيشمل العدّاد اللي اتنقل بالغلط من بادئة قديمة، حتى لو البادئة اتصححت قبل كده. أكواد الطلاب الحاليين وملكية الأكواد ما بتتغيرش.

العملية مش بتمسح طلبات أو طلاب أو درجات. لو البادئة الجديدة فيها كود مستخدم، التصحيح بيحافظ عليه وبيبدأ بعد أعلى رقم مسجّل فيها.

## حجز الكود وتحريره

- **حجز كود غير مستخدم:** بيوقف تخصيصه مؤقتًا. تقدر تحرره بعد مراجعة السجلات والتأكيد إنه ما اتخصصش قبل كده.
- **تحرير فجوة:** للأرقام اللي مالهاش مالك أو تاريخ تخصيص أو سجل أكاديمي مرتبط. اكتب سبب المراجعة وأكّد فحص السجلات. الكود المحرر بيتاخد بالأولوية في الموافقة التالية لنفس الدفعة.
- **كود طالب سابق:** بيفضل محظور بعد حذف حسابه لحد قرار مدير النظام. من الثلاث نقط، المدير يقدر يختار «تحرير الكود لإعادة الاستخدام» أو «حظر إعادة استخدام الكود». التحرير مش بيطلب إقرار خاطئ إن الكود لم يُستخدم.
- **أرشيف المالك السابق:** التحرير الإداري بينقل السجلات المرتبطة بالكود من الجداول التشغيلية إلى `student_code_archived_records`، مع نسخة كاملة ورقم المستند والمالك السابق والمنفّذ والتاريخ. ده بيمنع ظهور درجات أو حضور الطالب القديم للطالب الجديد. الطلبات الملغية بتفضل في مكانها مع `formerStudentCode` وتفضل روابط متابعتها شغّالة. سجل التخصيص بيعرض عدد السجلات المعزولة لكل نوع. الأرشيف الكامل محفوظ في قاعدة البيانات ومش بيتعرض كدرجات للطالب الجديد.
- **حساب لسه موجود:** إجراء التحرير أو الحظر مش بيفصل حساب طالب موجود تلقائيًا. احذف الحساب والملف من مسار الحذف أولًا. لو السجلات أكتر من 1000 مستند في نوع واحد، العملية بتتوقف للمراجعة؛ مفيش نقل جزئي.
- **رفع ملفات قديمة بعد إعادة الاستخدام:** ملف الطلاب ما يقدرش يغيّر الرقم القومي لصاحب الكود الحالي. ملفات الدرجات والحضور وباقي البيانات المرتبطة بكود اتعاد استخدامه لازم تضم معرّف حساب الطالب الحالي أو رقمه القومي بجانب الكود. الكود وحده مش كفاية علشان نعرف الملف يخص أي مالك.
- لو ظهرت رسالة إن الفحص اتغيّر، حدّث الفحص من نفس النافذة، راجع البيانات الجديدة وأكّد تاني. السبب اللي كتبته بيفضل موجود، وعلامات التأكيد بتتصفر.

## حذف الطالب

تقدر تحذف الطالب من قائمة الثلاث نقط في «تدقيق الأكواد»، بعد كتابة السبب والتأكيد. مدير النظام يقدر كمان يحذفه من صفحة الطلاب بعد قراءة رسالة التأكيد.

للأكواد الست أرقام، العملية بتحذف حساب الدخول وملف الطالب، وتلغي القبول المعتمد وتفضّي مقعد المجموعة. سجل الطلب وملكية الكود والسجلات الأكاديمية بيفضلوا محفوظين للمراجعة. الكود بيتحول لمحظور من إعادة الاستخدام لحد قرار إداري منفصل. كل الخطوات دي بتتم في معاملة واحدة؛ لو أي خطوة فشلت، العملية كلها بتتراجع. الأكواد القديمة اللي بصيغة مختلفة بتفضل على مسار الحذف القديم.

## الصلاحيات

كل إجراء على الأكواد محتاج صلاحية عرض التدقيق `student_codes.read`، ومعاها الصلاحية المناسبة:

| الإجراء | الصلاحية الإضافية |
| --- | --- |
| تهيئة السنة أو حجز كود غير مستخدم أو كود مالك سابق | `student_codes.manage` |
| تحرير فجوة أو فك حجز كود لم يُستخدم | `student_codes.recover` |
| حذف حساب طالب وإلغاء قبوله مع حجز الكود | `student_codes.delete_student` |
| تصدير التدقيق | `student_codes.export` |

مدير النظام عنده الصلاحيات دي. الموظف لازم تتضاف له صراحة؛ مش بتتضاف تلقائيًا لأي نوع موظف. تصحيح إعدادات بدايات الأعوام بيفضل لمدير النظام.

القرارات الجديدة «تحرير لإعادة الاستخدام»، «حظر إعادة الاستخدام»، و«اعتماد ربط الكود بالطالب وتصحيح سنة السجل» لمدير النظام فقط. صلاحية تحرير الفجوات للموظف مش بتسمح له بإعادة استخدام كود طالب سابق.

## اعتماد الطلاب المستوردين وتصحيح سنة السجل

لو الحساب والملف لنفس الطالب لكن سنة سجل الكود غلط، اختار سنة دفعة الكود واعمل فحص. افتح الثلاث نقط واختار «اعتماد ربط الكود بالطالب وتصحيح سنة السجل». راجع الطالب واكتب السبب وحدد المصدر حسب مستنداتك. الاعتماد بيصحح سنة سجل الكود بس، ومش بيغيّر كود الطالب أو سنته الدراسية الحالية. الكود بيبقى «مخصص ومحجوز للطالب» بعد الاعتماد. لو فيه تعارض بين مالك الحساب والملف أو سجل الملكية، لازم يتصلح الأول؛ الاعتماد مش بينقل ملكية كود من طالب لآخر.

## سجل التخصيص والرفع

سجل الكود بيعرض العملية، الحالة قبل وبعد، السبب، التاريخ بتوقيت القاهرة والمنفّذ لو حسابه لسه موجود. الرفع الجديد لملفات الطلاب بيسجّل اسم الملف ورقم عملية الرفع والدفعة ورقم الصف الأصلي بعد نجاح حفظ الملف ومطابقة الحساب والملف. الإضافة اليدوية بتتسجّل بمصدر «إضافة يدوية». عمود «آخر مصدر موثق» بيوضح آخر عملية مسجلة، ومش بيفترض إنها أول إضافة لو الطالب اتحدّث بعد كده. الموافقات الجديدة من ملفات القبول بتتسجّل بمصدر الاستيراد كمان.

البيانات القديمة ممكن يكون مصدرها ووقت إضافتها مش متسجلين. عند اعتماد الربط، تقدر تقرّ إن المصدر رفع أو يدوي حسب مستنداتك، أو تسيبه «مصدر قديم غير موثق». الإقرار بيظهر إنه تأكيد من مدير النظام بتاريخ المراجعة الحالي، منفصل عن المصدر اللي اتسجّل تلقائيًا وقت الرفع. مفيش اختراع لتاريخ رفع قديم. تهيئة السنة بتسجّل المالك اللي اتلاحظ وقت المراجعة. رفع ملف ما يقدرش يتجاوز كود محجوز في سجل الأكواد.

## ملاحظات التشغيل

الحجز والتحرير والحذف والتخصيص محتاجين MongoDB replica set. أول عملية كتابة بتجهّز فهرسًا فريدًا للتسلسل داخل السنة والبادئة، وبعده بتستبدل قيد السنة القديم. كمان بتستبدل قيد البادئة التاريخية بقيد البادئة الفعلية للتخصيص. مفيش مستندات أو أكواد بتتمسح ضمن تحديث الفهارس.

قبل النشر شغّل `pnpm run lint` و`pnpm run typecheck` و`pnpm run test -- --runInBand` و`pnpm run build`. شغّل `pnpm run test:admissions:services` وبعده `pnpm run test:admissions:e2e` لاختبار المعاملات على قاعدة محلية معزولة. ما تستخدمش قاعدة الإنتاج للاختبارات.
